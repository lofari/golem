## What needs to happen next

### High priority

1. **Wire event stream to runs provider.** The `RunsNotifier` exists but nothing feeds it events yet. The `stateWatchUrl(projectId)` WebSocket currently sends state-change messages; the Go server (`internal/server/`) needs to also broadcast `EngineEvent` lines on this channel (or a new `/api/events` endpoint). Then `AppShell` needs to initialize the event stream (currently the `runEventStreamProvider` from the plan was not wired because the server-side broadcast doesn't exist yet).

2. **Wire xterm.dart into `DetailTerminal`.** The placeholder is there; it needs to use the existing `processTerminalProvider` from `providers/processes.dart` to attach to a running process's WebSocket stream.

3. **Server-side: broadcast engine events.** `internal/server/` needs to forward `EngineEvent` NDJSON from the run's `log.json` to connected WebSocket clients. This is the missing link between the Go engine and the Flutter UI.

### Medium priority

4. **Agent discovery API.** `ProjectWorkspace` hardcodes `['build-feature', 'one-shot', 'fix-bug']`. Add a `/api/projects/{id}/agents` endpoint that lists `.ctx/agents/*.yaml` + embedded templates.

5. **Pipeline state polling.** `DetailState` accepts `pipelineState` but nothing fetches it yet. Add a REST endpoint or WebSocket message for the current `state.json` from the active run.

6. **Run persistence across app restarts.** `RunsNotifier` is in-memory. Consider loading recent runs from `.ctx/runs/*/log.json` on startup.

### Low priority

7. **Delete `launch_dialog.dart` and `project_switcher.dart`** — replaced by command bar and rail respectively. Left in place to avoid breaking any remaining references.

8. **Animated transitions** on rail expand/collapse and tab switching.
